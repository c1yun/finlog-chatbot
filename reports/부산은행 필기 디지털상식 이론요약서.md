## 1장 빅데이터·데이터 처리 ★부산 2020하·2021하(하둡·맵리듀스)·★경남 2024하

### 1.1 빅데이터 정의·V 체계·데이터 유형
- 정의: 기존 DB 관리도구의 수집·저장·관리·분석 역량을 넘어서는 대량의 정형·비정형 데이터 집합과 가치를 추출·분석하는 기술 ([TTA 용어사전](https://terms.tta.or.kr/), 원문 미열람·정설 정의).
- 3V(가트너 2001) Volume·Velocity·Variety → 5V +Veracity·Value → 7V +Variability·Visualization(교재별 상이).

- 데이터 유형: 정형(고정 스키마 행/열; RDB 테이블·거래원장·CSV) / 반정형(태그로 구조 표현; XML·JSON·HTML·로그) / 비정형(구조 없음; 텍스트·이미지·영상).

- 출제 포인트: "3V에 Value 포함" → X(5V). "JSON·XML은 비정형" → X(반정형). "이미지는 반정형" → X.

### 1.2 저장 아키텍처·처리 방식

| 구분 | DW | 데이터 마트 | 데이터 레이크 | 레이크하우스 |
|---|---|---|---|---|
| 데이터·스키마 | 정제 정형, Schema-on-Write | DW의 부서별 부분집합 | 원본(raw) 전부, Schema-on-Read | 레이크 저장+DW 관리(ACID) |
| 적재 | ETL(추출→변환→적재) | ETL | ELT(추출→적재→변환) | ELT |

- OLTP(일상 거래 처리, 현재·정규화, INSERT/UPDATE) vs OLAP(의사결정 분석, 이력·비정규화 스타 스키마, 드릴다운·롤업·슬라이스·다이스·피벗).

- 함정: "코어뱅킹=OLAP" → X(OLTP). "데이터 마트가 DW보다 크다" → X. 거버넌스 없이 방치된 레이크 = 데이터 늪.

### 1.3 하둡 ★부산 2021하
- 정의: 아파치 오픈소스 분산처리 프레임워크. 범용 서버 클러스터에 분산 저장(HDFS)·병렬 처리(MapReduce). 구글 GFS(2003)·MapReduce(2004) 논문을 더그 커팅이 구현(2006).

| 구성요소 | 역할 | 핵심 |
|---|---|---|
| HDFS | 분산 파일 저장 | NameNode(메타데이터)+DataNode(실제 블록), 블록 128MB(1.x 64MB), 복제 3 |
| MapReduce | 분산 병렬 처리 | Map("bank",1) → Shuffle/Sort(같은 키 정렬, 자동) → Reduce("bank",5) |
| YARN | 자원 관리·스케줄링(2.0에서 분리) | ResourceManager/NodeManager |

- 에코시스템: Hive(SQL 질의), HBase(컬럼형 NoSQL), Sqoop, Flume, Zookeeper, Kafka, Spark.
- 함정: "NameNode가 실제 데이터 저장" → X. "하둡은 실시간 처리" → X(배치). "YARN은 1.0부터" → X. "Shuffle은 프로그래머 구현" → X. "고가 전용 서버 필요" → X(Scale-out).

### 1.4 스파크 vs 맵리듀스 / NoSQL

| 구분 | 하둡 MapReduce | Spark |
|---|---|---|
| 처리 | 디스크 기반 | **인메모리**(반복 연산 10~100배, 스파크 측 주장) |
| 추상화 | (키,값) | **RDD**(불변, 계보로 복구) |
| 유형 | 배치 | 배치+스트리밍+SQL+MLlib |
| 저장소 | HDFS | 자체 없음(HDFS·S3 이용, 보완 관계) |

- NoSQL 4유형: 키-값(Redis, 캐시)·문서(MongoDB)·컬럼형(HBase·Cassandra)·그래프(Neo4j, FDS 네트워크). CAP(일관성·가용성·분할내성 중 둘) / RDB=ACID / NoSQL=BASE(결과적 일관성).
- 함정: "스파크는 하둡을 완전 대체" → X. "NoSQL은 SQL을 전혀 안 씀" → X. "NoSQL은 수직 확장 유리" → X(수평).

### 1.5 데이터 마이닝 ★경남 2024하

| 기법 | 학습 | 알고리즘 | 금융 예 |
|---|---|---|---|
| 분류 | 지도 | 의사결정나무, 로지스틱, SVM | 대출 승인, 사기 탐지 |
| 회귀 | 지도 | 선형·다중회귀 | 소득 추정 |
| 군집 | 비지도 | K-means, DBSCAN | 고객 세분화 |
| 연관규칙 | 비지도 | Apriori, FP-Growth | 장바구니·교차판매 |
| 이상탐지 | 비지도·반지도 | Isolation Forest, 오토인코더 | FDS |

- 연관규칙(X→Y): **지지도** P(X∩Y) / **신뢰도** P(Y|X) / **향상도** 신뢰도÷지지도(Y). Lift>1 양의 상관, =1 독립, <1 음의 상관. 예: 100건, X 40, Y 50, 둘 다 20 → 지지도 0.2, 신뢰도 0.5, 향상도 1.0(독립).
- 분석 4단계: 기술 → 진단 → 예측 → 처방. 텍스트 마이닝(TF-IDF·LDA). 크롤링(수집) vs 스크래핑(추출, 금융 마이데이터 금지).
- 함정: "향상도 1 미만이면 유의미" → X. "신뢰도 높으면 항상 유용" → X.

### 1.6 비식별화·프라이버시 모델
- 가명처리(개인정보보호법 §2 1의2): 일부 삭제·대체로 **추가 정보 없이는 개인 식별 불가**하게 처리 ([보안뉴스](https://m.boannews.com/html/detail.html?idx=93127)).

- 데이터 거버넌스 = 데이터 가용성·무결성·보안을 위한 정책·책임 체계(MDM). 데이터산업법 시행 2022.4.20 (확인 필요). 가명정보 결합 기대효과 ([보안뉴스 2023](https://m.boannews.com/html/detail.html?idx=117567)), 가명정보 활용 연구 ([KoreaScience](https://koreascience.or.kr/article/JAKO202129857848062.pdf)).
- 함정: "가명정보=익명정보" → X(가명정보는 법 적용). "마스킹된 번호는 익명정보" → X.

## 3장 AI·머신러닝·딥러닝 기초 ★경남 2024하

### 3.1 포함관계·학습 유형
- AI ⊃ ML ⊃ DL. AI(1956 다트머스, 매카시), ML(새뮤얼 1959, 데이터로 패턴 학습), DL(다층 신경망; 2012 AlexNet·2016 알파고). 생성형 AI = 새 콘텐츠 생성(판별형과 대비).

| 유형 | 정의 | 과제·예 |
|---|---|---|
| 지도학습 | 레이블 있는 데이터 | 분류·회귀(로지스틱, SVM, 랜덤포레스트) |
| 비지도학습 | 레이블 없이 구조 발견 | 군집(K-means)·차원축소(PCA)·연관규칙 |
| 강화학습 | 환경 상호작용, **보상** 최대화 | 알파고, 포트폴리오; RLHF |
| 준지도 / 자기지도 | 소량 레이블+대량 비레이블 / 데이터 자체에서 레이블 | — / LLM 사전학습 |

### 3.2 신경망·학습 기법
- 퍼셉트론(1958): 입력×가중치+편향 → 활성화함수. 단층은 XOR 불가 → 다층+역전파(1986). 활성화: 시그모이드·tanh·**ReLU**(기울기 소실 완화)·Softmax(다중분류).
- 역전파 = 오차를 역방향 전파해 기울기 계산; 경사하강법 = 손실 감소 방향으로 학습률만큼 갱신(Adam). 에포크 = 전체 데이터 1회. 기울기 소실 → ReLU·배치정규화·LSTM.

- 구조: CNN(합성곱·풀링, 이미지·OCR) / RNN·LSTM(시퀀스, 게이트로 장기 기억, 환율 예측) / GAN(생성자 vs 판별자, 딥페이크) / 오토인코더(압축→복원, FDS 이상탐지) / 트랜스포머(어텐션, LLM).

- 과적합(분산↑) 대책: 데이터 증강·정규화(L1·L2·드롭아웃)·조기 종료·교차검증(k-fold). 과소적합 = 편향↑.

### 3.3 평가지표

| | 예측 P | 예측 N |
|---|---|---|
| 실제 P | TP | FN(2종 오류) |
| 실제 N | FP(1종 오류) | TN |

- 정확도 (TP+TN)/전체 / **정밀도** TP/(TP+FP) / **재현율** TP/(TP+FN) / **F1** 2PR/(P+R)(조화평균) / ROC-AUC. 예: TP 40·FP 10·FN 20·TN 30 → 정확도 0.7, 정밀도 0.8, 재현율 0.667, F1≈0.727.
- 함정: "희소 사기거래 탐지에 정확도가 최선" → X(정확도 역설; 재현율·F1). "재현율↑이면 정밀도↑" → X. "F1은 산술평균" → X.

### 6.1 서비스·배포 모델

| 구분 | 정의 | 사용자 관리 | 예 |
|---|---|---|---|
| IaaS | 인프라 가상화 제공 | OS·미들웨어·앱·데이터 | AWS EC2/S3 |

## 7장 블록체인·CBDC·스테이블코인·토큰증권·가상자산·비단 ★부산 2020하·★경남 2023하·2024하

### 7.1 블록체인 기초
- 정의: 거래 기록(블록)을 해시로 연결(체인)해 노드가 분산 저장·검증하는 분산원장(DLT). 특징 = 탈중앙화·불변성·투명성·가용성·가명성. 법적 정의: 토큰증권법이 전자증권법에 "블록체인 기반 분산원장" 개념 신설 ([금융위 86064](https://www.fsc.go.kr/no010101/86064)).
- 블록 = 헤더(이전 해시·머클루트·타임스탬프·난이도·논스)+바디(거래). 해시 = 고정 길이 일방향(SHA-256). 머클트리 = 거래 요약·포함 검증. 논스 = PoW 채굴 시 바꾸는 값.

- 합의: PoW(해시 퍼즐, 전력 소모·약 10분; 비트코인) / PoS(지분 비례 검증자, 효율; 이더리움 2022.9 머지) / DPoS(투표 대표 노드; EOS) / PBFT(허가 노드 2/3 초과 동의, 즉시 최종성; 하이퍼레저).

| 구분 | 퍼블릭 | 프라이빗 | 컨소시엄 |
|---|---|---|---|
| 참여 | 누구나(비허가) | 단일 기관 허가 | 복수 기관 공동(허가) |
| 속도·탈중앙 | 낮음·높음 | 높음·낮음 | 높음·중간 |
| 암호화폐 | 보통 필요 | 불필요 | 불필요 |
| 예 | 비트코인·이더리움 | 기업 내부 원장 | 하이퍼레저 패브릭·R3 코다 |

- 스마트 계약(조건 충족 시 자동 실행, 이더리움·솔리디티·가스), ERC-20·ERC-721(NFT). 반감기 약 4년(2024.4 4차, 일자 확인 필요), 총 2,100만 개. 51% 공격. 하드포크(비호환, 체인 분리) vs 소프트포크(하위 호환). L2(롤업). 핫 vs 콜드월렛. 트릴레마 = 탈중앙화·보안성·확장성.
- 함정: "비트코인은 PoS" → X. "소프트포크는 체인 분리" → X. "콜드월렛은 상시 온라인" → X. "프라이빗은 누구나 참여" → X.

### 7.2 CBDC·예금토큰 — 프로젝트 한강 ★경남 2024하(디지털화폐 vs 전통화폐)
- CBDC = 중앙은행 발행·액면가 고정 디지털화폐(암호자산은 민간·변동) ([KB Think](https://kbthink.com/crypto/what-is-cbdc.html)). 구조: 한은 **기관용(도매) CBDC** 발행 → 은행이 **예금토큰** 발행 → 개인 사용(2계층) ([헤럴드경제 7.19](https://www.heraldk.com/article/2026071917255421848)).

| 구분 | 1단계 | 2단계 |
|---|---|---|

## 11장 IT 기초(네트워크·DB·OS·프로그래밍·자료구조)

### 11.1 네트워크

| OSI | 프로토콜 / 단위 | 장비 |
|---|---|---|
| 7 응용·6 표현·5 세션 | HTTP·FTP·SMTP·DNS / TLS / RPC | 게이트웨이·WAF |
| 4 전송 | **TCP·UDP** / 세그먼트 | L4 스위치 |
| 3 네트워크 | **IP·ICMP·ARP** / 패킷 | **라우터** |
| 2 데이터링크 / 1 물리 | Ethernet / 프레임 / 비트 | **스위치** / **허브** |

- TCP(연결지향, 3-way handshake, 재전송 보장) vs UDP(비연결, 빠름; DNS·스트리밍). IPv4 32비트 vs IPv6 128비트; 사설 IP→NAT ([RFC 1918](https://www.rfc-editor.org/rfc/rfc1918)); /24 = 254 호스트. DNS 53·DHCP·ARP(IP→MAC).
- HTTP 80 / HTTPS 443. GET·POST·PUT·PATCH·DELETE. 상태코드 200·201·301/302·400·**401 인증**·**403 인가**·404·500·503 ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110)). 허브(1계층 브로드캐스트) vs 스위치(2계층 MAC 테이블) vs 라우터(3계층).

### 11.2 데이터베이스
- SQL: **DDL**(CREATE·ALTER·DROP·TRUNCATE) / **DML**(SELECT·INSERT·UPDATE·DELETE) / **DCL**(GRANT·REVOKE) / TCL(COMMIT·ROLLBACK). "DELETE는 DDL" → X.
- 키: 기본키(유일+NOT NULL), 후보키, 외래키(참조 무결성). 정규화: 1NF 원자값 → 2NF 부분함수종속 제거 → 3NF 이행함수종속 제거 → BCNF. 반정규화 = 성능 위한 중복. ACID. 인덱스(검색↑, 갱신 비용↑, B-tree). RDBMS(Oracle·MySQL, 수직 확장) vs NoSQL(1장).

### 11.3 OS·프로그래밍·자료구조·웹
- 프로세스(독립 메모리) vs 스레드(메모리 공유, 문맥교환 저렴). 가상메모리(페이징). 데드락 4조건: 상호배제·점유대기·비선점·순환대기. 스케줄링 FCFS·SJF·라운드로빈.
- 컴파일러(C·Java) vs 인터프리터(Python·JS). 객체지향 4원칙 캡슐화·상속·다형성·추상화. 워터폴 vs 애자일(스크럼). CI/CD, Git. GPL(카피레프트) vs MIT·Apache. 테스트 단위→통합→시스템→인수.
- 자료구조: 스택(LIFO)·큐(FIFO)·연결리스트·이진탐색트리 O(log n)·해시 O(1)·그래프(BFS/DFS). 정렬 버블·선택·삽입 O(n²), 퀵 평균 n log n, 병합 n log n. 이진 탐색 O(log n, 정렬 필요). 빅오 O(1)<O(log n)<O(n)<O(n log n)<O(n²)<O(2ⁿ).
- 웹: 쿠키(클라이언트) vs 세션(서버) vs JWT(헤더.페이로드.서명; **페이로드는 Base64 인코딩, 암호화 아님**). OAuth 2.0 = 권한 위임(인가), OpenID Connect = 인증.
- 수 체계: 2진 1010=10, 16진 FF=255. ASCII 7비트 → UTF-8(한글 3바이트), EUC-KR(2바이트). 메모리 계층 레지스터>캐시>RAM>SSD. 참조: [ISO/IEC 7498-1](https://www.iso.org/standard/20269.html), [RFC 1122](https://www.rfc-editor.org/rfc/rfc1122), [RFC 8446](https://www.rfc-editor.org/rfc/rfc8446), [NIST SP 800-38A](https://csrc.nist.gov/pubs/sp/800/38/a/final).
- 함정: "스레드는 메모리 비공유" → X. "JWT 페이로드는 암호화" → X. "401은 인가 실패" → X(인증).
