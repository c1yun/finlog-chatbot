## KQ1. 빅데이터 개념·기술(3V→7V, 저장구조, 하둡·맵리듀스·스파크, NoSQL, 데이터 마이닝, 비식별화)

### Takeaway
부산은행은 2021 하반기 "하둡·맵리듀스"를 실제 출제했고(디지털 전공자도 당황), 경남은행은 데이터마이닝·클라우드 XaaS를 4개 회차 반복 출제했다. 정의형(3V, 하둡 구성요소, 맵리듀스 단계, 정형/비정형, 레이크 vs 웨어하우스)과 비교형(ETL/ELT, OLTP/OLAP, 하둡/스파크, SQL/NoSQL) OX가 핵심이다.

### Cited Findings

#### (1) 빅데이터 정의와 V 체계 [교과서]
- 정의(TTA 정보통신용어사전 요지): 기존 데이터베이스 관리도구로 수집·저장·관리·분석할 수 있는 역량을 넘어서는 대량(수십 TB~PB 이상)의 정형·비정형 데이터 집합 및 이로부터 가치를 추출하고 결과를 분석하는 기술 — [TTA 정보통신용어사전(검색: 빅데이터)](https://terms.tta.or.kr/) (본 세션에서 페이지 원문은 열지 못함, 정의 요지는 교과서 정설)
- 3V(가트너 더그 레이니, 2001): Volume(규모)·Velocity(속도)·Variety(다양성) → 5V: +Veracity(정확성/신뢰성)·Value(가치) → 7V: +Variability(가변성)·Visualization(시각화) (교재에 따라 Validity·Volatility 등 변형 있음) [교과서]

| 구분 | 3V | 5V 추가 | 7V 추가(교재별 상이) |
|---|---|---|---|
| 요소 | Volume·Velocity·Variety | Veracity·Value | Variability·Visualization(또는 Validity·Volatility) |
| 함정 | "3V에 Value 포함" → X(Value는 5V) | Veracity=정확성·신뢰성(≠Validity 타당성) | 7V 구성은 교재마다 달라 '정답 고정' 아님 |

#### (2) 데이터 유형 [교과서]
| 유형 | 정의 | 예시 | 저장 |
|---|---|---|---|
| 정형(Structured) | 고정된 스키마·행/열 구조 | RDBMS 테이블, 엑셀, 거래원장, CSV | RDB/DW |
| 반정형(Semi-structured) | 스키마는 없으나 메타데이터·태그로 구조 표현 | XML, JSON, HTML, 로그파일, 이메일 헤더 | NoSQL/데이터 레이크 |
| 비정형(Unstructured) | 구조 없음 | 텍스트, 이미지, 음성, 영상, SNS 글 | 데이터 레이크/객체 스토리지 |
- OX 포인트: "JSON·XML은 비정형" → X(반정형). "이미지·동영상은 반정형" → X(비정형). "전체 데이터의 80% 이상이 비정형"은 통상 인용되는 추정치(출처별 상이).

#### (3) 저장 아키텍처 비교 [교과서]
| 구분 | 데이터 웨어하우스(DW) | 데이터 마트(DM) | 데이터 레이크(DL) | 레이크하우스 |
|---|---|---|---|---|
| 데이터 | 정제된 정형 데이터 | DW의 부서·주제별 부분집합 | 원본(raw) 정형+비정형 전부 | 레이크의 저장 + DW의 관리(ACID·스키마) |
| 스키마 | Schema-on-Write(저장 시 정의) | 동일 | Schema-on-Read(읽을 때 정의) | 둘 다 지원 |
| 사용자 | 경영분석(BI) | 특정 부서 | 데이터 과학자 | 양쪽 |
| 적재 | ETL | ETL | ELT | ELT 중심 |
| 대표 | Teradata, Redshift, BigQuery | — | HDFS, S3 | Databricks Delta Lake, Snowflake |
- 함정: "데이터 마트가 DW보다 크다" → X(마트는 DW의 부분집합). "데이터 레이크는 정형 데이터만" → X. "데이터 늪(Data Swamp)"=거버넌스 없이 방치된 레이크.

| 구분 | ETL | ELT |
|---|---|---|
| 순서 | 추출(Extract)→변환(Transform)→적재(Load) | 추출→적재→(목적지 내에서)변환 |
| 적합 | DW, 정형, 규제 데이터 | 데이터 레이크, 클라우드 DW, 대용량 |
| 변환 장소 | 별도 스테이징 서버 | 목적지 DB/레이크의 연산력 |

| 구분 | OLTP(온라인 트랜잭션 처리) | OLAP(온라인 분석 처리) |
|---|---|---|
| 목적 | 일상 거래 처리(입출금·이체) | 의사결정 분석(다차원 집계) |
| 질의 | 짧고 빈번한 읽기/쓰기 | 길고 복잡한 읽기 중심 |
| 데이터 | 현재·정규화 | 이력·비정규화(스타/스노플레이크 스키마) |
| 연산 | INSERT/UPDATE | 드릴다운·롤업·슬라이스·다이스·피벗 |
| 저장소 | 운영 DB | DW/DM, 데이터 큐브 |
- 함정: "은행 계정계(코어뱅킹)=OLAP" → X(OLTP). "DW는 OLTP용" → X.

#### (4) 하둡(Hadoop) ★복기 2021 하 [교과서]
- 정의: 아파치 재단의 오픈소스 분산처리 프레임워크. 범용(저가) 서버 여러 대를 클러스터로 묶어 대용량 데이터를 분산 저장(HDFS)하고 병렬 처리(MapReduce)한다. 구글의 GFS(2003)·MapReduce(2004) 논문을 더그 커팅이 구현(2006), 이름은 그의 아들 장난감 코끼리에서 유래 [교과서]
- 핵심 구성요소(하둡 2.x 이후 3대 요소):

| 구성요소 | 역할 | 핵심 용어 |
|---|---|---|
| HDFS(Hadoop Distributed File System) | 분산 파일 저장 | 마스터 NameNode(메타데이터) + 슬레이브 DataNode(실제 블록). 기본 블록 128MB(1.x는 64MB), 기본 복제계수 3(한 블록을 3곳에 복제 → 장애 허용) |
| MapReduce | 분산 병렬 처리 프로그래밍 모델 | Map → Shuffle/Sort → Reduce |
| YARN(Yet Another Resource Negotiator) | 클러스터 자원 관리·작업 스케줄링(하둡 2.0에서 분리) | ResourceManager / NodeManager / ApplicationMaster |
- 에코시스템: Hive(SQL 유사 질의 HiveQL), Pig(데이터 흐름 스크립트), HBase(컬럼형 NoSQL, HDFS 위), Sqoop(RDB↔HDFS 적재), Flume(로그 수집), Zookeeper(분산 코디네이션), Oozie(워크플로), Kafka(메시지 큐·스트리밍), Spark(인메모리 처리) [교과서]
- 맵리듀스 단계(워드카운트 예): ① Input Split(입력 분할) → ② **Map**: 각 레코드를 (키, 값) 쌍으로 변환 (예: ("bank",1)) → ③ **Shuffle & Sort**: 같은 키끼리 모아 정렬해 리듀서에 분배 (프레임워크가 자동 수행) → ④ **Reduce**: 키별로 값을 집계 (("bank", 5)) → ⑤ Output. Combiner는 Map 측 로컬 사전집계(선택) [교과서]
- OX 포인트: "HDFS는 NameNode가 실제 데이터를 저장" → X(메타데이터; 실제 블록은 DataNode). "하둡은 실시간 처리에 적합" → X(배치 처리; 실시간은 Spark Streaming/Flink/Storm). "YARN은 하둡 1.0부터" → X(2.0). "맵리듀스의 Shuffle은 프로그래머가 직접 구현" → X(Map·Reduce만 작성). "하둡은 고가의 전용 서버가 필요" → X(범용 서버 수평 확장(Scale-out)).

#### (5) 스파크 vs 하둡 맵리듀스 [교과서]
| 구분 | 하둡 MapReduce | 아파치 스파크(Spark) |
|---|---|---|
| 처리 방식 | 디스크 기반(중간 결과를 HDFS에 기록) | **인메모리** 기반(메모리에 유지) → 반복 연산 10~100배 빠름(스파크 측 주장) |
| 핵심 추상화 | (키,값) Map/Reduce | **RDD(Resilient Distributed Dataset, 탄력적 분산 데이터셋)** → DataFrame/Dataset |
| 처리 유형 | 배치 | 배치+스트리밍(Spark Streaming)+SQL(Spark SQL)+ML(MLlib)+그래프(GraphX) |
| 언어 | Java 중심 | Scala·Python(PySpark)·Java·R |
| 장애 복구 | 복제 | RDD 계보(Lineage)로 재계산 |
| 저장소 | HDFS | 자체 저장소 없음 → HDFS·S3·Cassandra 등 이용(하둡과 보완관계) |
- 함정: "스파크는 하둡을 완전히 대체한다" → X(저장은 HDFS 등 활용, YARN 위에서 실행 가능). "RDD는 변경 가능(mutable)" → X(불변, 변환 시 새 RDD 생성). "스파크는 지연 평가(lazy evaluation)" → O(Action 호출 시 실행).

#### (6) NoSQL(Not Only SQL) [교과서]
| 유형 | 구조 | 대표 | 용도 |
|---|---|---|---|
| 키-값(Key-Value) | 해시 테이블 | Redis, Amazon DynamoDB, Riak | 세션·캐시 |
| 문서(Document) | JSON/BSON 문서 | MongoDB, CouchDB | 콘텐츠·로그 |
| 컬럼형(Wide-Column) | 컬럼 패밀리 | HBase, Cassandra, Google Bigtable | 대규모 시계열·분석 |
| 그래프(Graph) | 노드·엣지 | Neo4j, Amazon Neptune | SNS 관계, 금융 사기탐지(FDS) 네트워크 분석 |
- 이론: CAP 정리(브루어) — 일관성(Consistency)·가용성(Availability)·분할내성(Partition tolerance) 중 둘만 보장. RDB=ACID(원자성·일관성·고립성·지속성), NoSQL=BASE(Basically Available, Soft state, Eventual consistency) [교과서]
- 함정: "NoSQL은 SQL을 전혀 쓰지 않는다" → X(Not Only SQL). "NoSQL은 수직 확장(Scale-up)에 유리" → X(수평 확장 Scale-out). "NoSQL은 조인·트랜잭션에 강하다" → X(RDB 강점).

#### (7) 데이터 마이닝 기법 [교과서]
| 기법 | 목표변수 | 학습 | 대표 알고리즘 | 금융 예 |
|---|---|---|---|---|
| 분류(Classification) | 범주형(있음) | 지도 | 의사결정나무, 로지스틱 회귀, SVM, 랜덤포레스트, KNN | 대출 승인/거절, 부도 예측, 사기 거래 탐지 |
| 회귀(Regression) | 연속형(있음) | 지도 | 선형·다중회귀 | 주택가격·소득 추정 |
| 군집(Clustering) | 없음 | 비지도 | K-means, 계층적 군집, DBSCAN | 고객 세분화(세그먼테이션) |
| 연관규칙(Association) | 없음 | 비지도 | Apriori, FP-Growth | 장바구니 분석("기저귀→맥주"), 교차판매 상품 추천 |
| 이상탐지(Anomaly) | 없음/있음 | 비지도·반지도 | Isolation Forest, 오토인코더 | FDS |
- 연관규칙 3지표(X→Y): **지지도(Support)**=P(X∩Y) 전체 거래 중 X와 Y를 함께 포함하는 비율 / **신뢰도(Confidence)**=P(Y|X)=지지도(X∩Y)/지지도(X), X를 산 거래 중 Y도 산 비율 / **향상도(Lift)**=신뢰도/지지도(Y)=P(X∩Y)/(P(X)P(Y)). Lift>1 양의 상관(함께 구매), =1 독립(우연), <1 음의 상관 [교과서]
  - 계산 예: 거래 100건, X 포함 40, Y 포함 50, 둘 다 20 → 지지도 0.2, 신뢰도 0.5, 향상도 0.5/0.5=1.0(독립).
  - 함정: "향상도 1 미만이면 유의미한 규칙" → X. "신뢰도가 높으면 항상 유용" → X(Y 자체가 흔하면 향상도 1에 가까움).
- 텍스트 마이닝: 비정형 텍스트에서 패턴·감성·주제를 추출(형태소 분석, TF-IDF, 감성분석, 토픽모델링 LDA, 워드클라우드). 크롤링(Crawling)=웹 페이지를 자동 수집하는 프로그램(크롤러·스파이더), 스크래핑=페이지에서 특정 데이터를 추출. 금융 마이데이터에서는 스크래핑이 금지되고 API로 전환(KQ2 참조) [교과서]
- 분석 유형 4단계: 기술(Descriptive, 무슨 일이) → 진단(Diagnostic, 왜) → 예측(Predictive, 무엇이 일어날지) → 처방(Prescriptive, 무엇을 해야) [교과서]

#### (8) 데이터 거버넌스·품질·시각화 [교과서]
- 데이터 거버넌스: 데이터의 가용성·유용성·무결성·보안을 보장하기 위한 조직의 정책·표준·프로세스·책임 체계(데이터 오너·스튜어드, 메타데이터·마스터데이터(MDM) 관리, 데이터 표준·사전). 국내 공공은 「데이터기반행정 활성화에 관한 법률」·「데이터 산업진흥 및 이용촉진에 관한 기본법(데이터산업법, 2022.4.20 시행)」이 근거 — 시행일은 (확인 필요)
- 데이터 품질 6대 기준(교재별): 정확성·완전성·일관성·적시성·유효성·유일성.
- 시각화: 시간(선), 비교(막대), 분포(히스토그램·박스플롯), 관계(산점도), 구성(파이·트리맵), 지리(코로플레스). 도구: Tableau, Power BI, matplotlib. 대시보드=KPI 한눈에.
- 데이터 라벨링(Labeling/Annotation): 지도학습용 정답(레이블)을 사람이 부여하는 작업(이미지 바운딩박스, 텍스트 태깅). 정부 'AI 학습용 데이터 구축(데이터 댐)' 사업과 연결. 크라우드소싱 라벨링(AI 데이터 라벨러 직업) [교과서]

| 기법 | 내용 | 예 |
|---|---|---|
| 가명처리(Pseudonymization) | 식별자를 다른 값으로 대체(휴리스틱 가명화, 암호화, 교환) | 홍길동→A01 |

- 프라이버시 보호 모델: k-익명성(동일 준식별자 조합이 k명 이상), l-다양성(민감속성이 l개 이상 다양), t-근접성(민감속성 분포가 전체와 t 이내) [교과서]
- 차분 프라이버시(Differential Privacy): 질의 결과에 수학적으로 보정된 잡음(noise)을 더해 특정 개인의 포함 여부를 결과로부터 추론할 수 없게 하는 기법(프라이버시 예산 ε). 애플·미국 센서스(2020)·구글이 적용. 가명처리(데이터 자체 변형)와 달리 '출력(통계)'을 보호 [교과서]
- 함정: "가명정보=익명정보" → X(가명정보는 추가정보 결합 시 재식별 가능, 여전히 개인정보로서 법 적용; 익명정보는 법 적용 제외). "마스킹된 전화번호는 익명정보" → X(단독으론 가명·비식별 조치일 뿐).

## KQ2. 데이터3법·개인정보보호법·마이데이터(본인신용정보관리업) ★복기 "마이데이터"

### Takeaway
데이터3법(2020.8.5 시행)은 가명정보 개념 도입·통계/연구/공익기록 목적의 동의 없는 활용·데이터전문기관 결합이 핵심이고, 2023년 전면개정 개인정보보호법(2023.9.15 시행)은 과징금 전체 매출액 3%·유출 72시간 신고·전송요구권(2025년 의료·통신·에너지부터 시행)을 도입했다. 금융 마이데이터는 2022.1.5 API 전면 시행(스크래핑 금지)→2025.6.18 「마이데이터 2.0」 서비스 개시(전 금융자산 일괄조회·가입 유효기간 최대 5년·14세 미만 법정대리인 동의)로 진화했다.

### Cited Findings

#### (1) 포함관계·학습 유형 [교과서]
- AI ⊃ 머신러닝(ML) ⊃ 딥러닝(DL). AI(1956 다트머스 회의, 존 매카시 명명): 인간의 지적 능력을 기계로 구현. ML(아서 새뮤얼 1959): 명시적 프로그래밍 없이 데이터로부터 패턴을 학습. DL: 다층 인공신경망(심층신경망)을 이용한 ML의 한 분야(2012 AlexNet·ImageNet 계기, 2016 알파고).
- 생성형 AI(Generative AI)는 DL 기반으로 새로운 콘텐츠(텍스트·이미지·음성·코드)를 생성하는 AI; 판별형(Discriminative) AI와 대비.

| 학습 유형 | 정의 | 대표 과제 | 알고리즘·예 |
|---|---|---|---|
| 지도학습(Supervised) | 정답(레이블) 있는 데이터로 학습 | 분류(스팸/정상, 부도 예측), 회귀(가격 예측) | 로지스틱회귀, SVM, 의사결정나무, 랜덤포레스트, 신경망 |

#### (2) 신경망 기초 [교과서]
- 퍼셉트론(로젠블랫 1958): 입력×가중치 합 + 편향 → 활성화함수 → 출력. 단층 퍼셉트론은 XOR 문제 해결 불가(민스키 1969) → 다층 퍼셉트론(MLP)+역전파(1986 루멜하트·힌튼)로 해결.
- 활성화함수: 계단, 시그모이드(0~1), tanh(-1~1), **ReLU**(max(0,x), 기울기 소실 완화, 딥러닝 기본), Softmax(다중분류 출력 확률).
- 역전파(Backpropagation): 출력 오차를 출력층→입력층 방향으로 전파하며 가중치의 기울기(gradient)를 계산. 경사하강법(Gradient Descent): 손실함수를 줄이는 방향(기울기 반대)으로 가중치를 학습률(learning rate)만큼 갱신. 변형: SGD(확률적), 미니배치, 모멘텀, Adam. 에포크(epoch)=전체 데이터 1회 학습, 배치(batch).
- 기울기 소실(vanishing gradient): 깊은 망에서 시그모이드 미분이 반복 곱해져 앞층이 학습되지 않는 현상 → ReLU·배치정규화·잔차연결(ResNet)·LSTM.

| 구조 | 특징 | 용도 |
|---|---|---|
| CNN(합성곱 신경망) | 합성곱(필터)·풀링으로 공간 특징 추출, 파라미터 공유 | 이미지 분류·객체 탐지(OCR, 신분증 인식) |
| RNN(순환 신경망) | 이전 상태를 순환 입력, 시퀀스 처리; 장기 의존성 문제 | 시계열·자연어 |
| LSTM/GRU | 게이트(입력·망각·출력)로 장기 기억 유지 | 주가·환율 예측, 음성 |
| GAN(생성적 적대 신경망, 굿펠로 2014) | 생성자(Generator) vs 판별자(Discriminator) 경쟁 학습 | 이미지 생성, 딥페이크, 데이터 증강 |
| 오토인코더 | 입력→압축(인코더)→복원(디코더), 비지도 | 차원축소·이상탐지(FDS)·노이즈 제거 |
| 트랜스포머 | 어텐션만으로 시퀀스 처리(순환 없음) → 병렬화 | LLM·번역·이미지(ViT) |
- 과적합(Overfitting): 훈련 데이터에 과도하게 맞아 새 데이터 성능 저하(분산↑). 대책: 데이터 증강, **정규화(Regularization: L1 라쏘·L2 릿지, 드롭아웃)**, 조기 종료, 교차검증, 모델 단순화. 과소적합(Underfitting)=편향↑. 편향-분산 트레이드오프.
- 교차검증(k-fold): 데이터를 k등분해 k-1개로 학습, 1개로 검증을 k회 반복 후 평균. 훈련/검증/테스트 분할(예 60/20/20). 홀드아웃.
- 혼동행렬(이진분류, 양성=P):

| | 예측 P | 예측 N |
|---|---|---|
| 실제 P | TP | FN(2종 오류, 놓침) |
| 실제 N | FP(1종 오류, 오탐) | TN |
- 정확도(Accuracy)=(TP+TN)/전체 / **정밀도(Precision)**=TP/(TP+FP) "양성이라 한 것 중 진짜" / **재현율(Recall, 민감도)**=TP/(TP+FN) "실제 양성 중 잡아낸 비율" / 특이도=TN/(TN+FP) / **F1**=2·P·R/(P+R)(조화평균) / ROC-AUC. 계산 예: TP 40, FP 10, FN 20, TN 30 → 정확도 0.7, 정밀도 0.8, 재현율 0.667, F1≈0.727.
- 함정: "사기거래(희소) 탐지에 정확도가 최선 지표" → X(불균형 데이터에서 정확도 역설; 재현율·F1·AUC). "재현율↑이면 정밀도도 ↑" → X(트레이드오프). "F1은 산술평균" → X(조화평균).

#### (3) 트랜스포머·LLM 용어 [교과서 + 역사적 사실]
- 트랜스포머: 2017년 구글 논문 "Attention Is All You Need"(Vaswani 외)에서 제안, 순환(RNN)·합성곱 없이 **셀프 어텐션(Self-Attention)**으로 토큰 간 관계를 계산, 인코더-디코더 구조, 멀티헤드 어텐션, 위치 인코딩(positional encoding). 인코더 계열=BERT(양방향, 이해), 디코더 계열=GPT(자기회귀 생성), 인코더-디코더=T5·번역 — [arXiv 1706.03762](https://arxiv.org/abs/1706.03762) (원문 미열람, 서지 정설)
- 용어 정리:

| 용어 | 정의 |
|---|---|
| 파라미터(Parameter) | 모델이 학습으로 얻은 가중치·편향의 수(GPT-3 1,750억 개). 모델 '크기' 지표 |
| 토큰(Token) | 모델이 처리하는 텍스트 최소 단위(단어·서브워드·문자). 영어 약 0.75단어/토큰, 한국어는 더 많은 토큰 소모 |
| 컨텍스트 윈도우 | 한 번에 입력+출력으로 처리 가능한 최대 토큰 수(수천~수백만 토큰) |
| 임베딩(Embedding) | 단어·문장·이미지를 의미를 보존하는 고차원 실수 벡터로 변환(Word2Vec, BERT 임베딩) |
| 벡터 DB | 임베딩 벡터를 저장하고 유사도(코사인) 검색하는 DB(Pinecone, Milvus, Chroma, FAISS, pgvector) — RAG의 핵심 인프라 |
| 파운데이션 모델 | 대규모 데이터로 사전학습되어 다양한 하위 과제에 적응 가능한 범용 모델(스탠퍼드 HAI 2021 용어). LLM은 언어 파운데이션 모델 |
| LLM / sLLM | 대규모 언어모델 / 소형 언어모델(수십억 파라미터 이하, 온디바이스·비용 절감·기업 특화. 예: Llama 3 8B, Gemma, EXAONE 소형, HyperCLOVA X Dash) |
| 할루시네이션(환각) | 그럴듯하지만 사실이 아닌 내용을 생성하는 현상(확률적 다음 토큰 예측의 한계). 대책: RAG, 근거 제시, 온도(temperature) 낮춤, 검증 |
| RAG(검색 증강 생성) | 질문에 대해 외부 지식베이스(벡터 DB)를 먼저 검색(Retrieval)해 관련 문서를 프롬프트에 넣고 생성(Generation). 최신·사내 정보 반영, 환각 감소, 재학습 불필요. 금융권 내부 규정 챗봇의 표준 구조 |
| 파인튜닝(미세조정) | 사전학습 모델의 가중치를 특정 과제 데이터로 추가 학습(SFT, LoRA·PEFT로 비용 절감). 모델 자체가 바뀜 |
| 프롬프트 엔지니어링 | 모델 가중치 변경 없이 입력 지시문을 설계(역할 부여, 예시, 단계적 사고 CoT). |
| 인컨텍스트 러닝 | 프롬프트 안의 예시만으로 과제를 수행(학습 없음). 제로샷(예시 0), 원샷(1), 퓨샷(소수 예시) |
| 멀티모달 | 텍스트·이미지·음성·영상 등 복수 양식을 입출력(GPT-4o, Gemini) |
| 온도(temperature) | 출력 무작위성 조절(0 결정적↔높을수록 다양) |
- 비교 함정: "RAG는 모델을 재학습시킨다" → X(검색 결합, 가중치 불변). "파인튜닝이 항상 RAG보다 최신 정보 반영에 유리" → X(RAG가 유리). "제로샷=예시 하나" → X(0개). "토큰=단어" → X(서브워드 단위).

#### (5) AI 에이전트·에이전틱 AI·MCP·A2A [교과서/업계 정의]
- AI 에이전트: LLM이 목표를 받아 스스로 계획(Planning)→도구 사용(Tool use: 검색·API·DB)→실행→관찰을 반복하며 과업을 자율 수행하는 시스템. 챗봇(질의응답)과의 차이=자율성·도구 호출·다단계 수행. 에이전틱 AI(Agentic AI)=여러 에이전트가 협업하는 자율 시스템 전반.
- **MCP(Model Context Protocol)**: Anthropic이 2024.11 공개한 오픈 표준. LLM 애플리케이션(호스트)이 외부 도구·데이터 소스(서버)에 표준화된 방식으로 연결하는 프로토콜("AI의 USB-C"). 2025년 OpenAI·구글 등 채택 — 날짜·채택 현황 (확인 필요, 업계 상식).
- **A2A(Agent2Agent)**: 구글이 2025.4 공개한 에이전트 간 통신 개방 프로토콜(에이전트 카드로 역량 공개, 작업 위임). MCP=에이전트↔도구, A2A=에이전트↔에이전트로 보완 관계 — (확인 필요).
- 금융권 적용 흐름(KQ4 검증 자료): 우리은행 175개 에이전트, NH '나이스(NHAIS)', 하나은행 "AI뱅킹의 종착지는 에이전트", 금융위 "AI 에이전트 테스트 시범사업"(2026 하반기 TF).
- OX: "MCP는 에이전트끼리 대화하는 프로토콜" → X(모델↔도구·데이터; 에이전트 간은 A2A). "AI 에이전트는 규칙 기반 RPA와 동일" → X(RPA는 정해진 규칙 반복, 에이전트는 LLM 추론·계획).
