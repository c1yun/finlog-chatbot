## 핵심 질문 1. 보안 개념(CIA·제로트러스트·인증·암호·PQC·보안장비·망분리·취약점·BCP·접근통제·거버넌스·전자금융감독규정·금융보안원)

### Takeaway
정의형 문항의 뼈대는 "CIA 3요소+인증·부인방지", "인증 3요소(지식·소유·속성)", "대칭키 vs 비대칭키 vs 해시", "제로트러스트 = '절대 신뢰하지 말고 항상 검증'(NIST SP 800-207, 2020.8)"이며, 2026년 시사 연결 포인트는 망분리 완화(2026.4.20 SaaS 허용 → 5월 보안목적 AI 예외 → 7월 전면 해제 추진) 속에서 금융보안원이 2026.4.9 「금융분야 제로트러스트 보안 안내서」를 낸 것, NIST PQC 표준(FIPS 203/204/205, 2024.8.13) 이후 금융보안원이 2025.7 PQC 전환 보고서를 배포한 것이다.

### Cited Findings

**(1) 정보보안 3요소 + 확장 요소** [교과서]
| 요소 | 정의(1~2문장) | 대표 기술 | 침해 예 |
|---|---|---|---|
| 기밀성 Confidentiality | 인가된 자만 정보에 접근할 수 있도록 보장 | 암호화, 접근통제 | 개인정보 유출 |
| 무결성 Integrity | 정보가 인가되지 않은 방식으로 변조·파괴되지 않음을 보장 | 해시, 전자서명, MAC | 데이터 위·변조 |
| 가용성 Availability | 인가된 사용자가 필요할 때 정보·시스템을 쓸 수 있음을 보장 | 이중화, 백업, DDoS 방어 | DDoS, 랜섬웨어 |
| 인증 Authentication | 사용자·시스템이 주장하는 신원이 맞는지 확인 | 비밀번호, OTP, 생체 | 계정 탈취 |
| 부인방지 Non-repudiation | 행위자가 송·수신 사실을 나중에 부인하지 못하게 함 | 전자서명(개인키 서명) | "내가 보낸 적 없다" |
- 근거: NIST SP 800-12/FIPS 199의 C-I-A 정의 — [NIST FIPS 199](https://csrc.nist.gov/pubs/fips/199/final); TTA 정보통신용어사전 — [terms.tta.or.kr](https://terms.tta.or.kr/) (본 세션 미열람)
- **함정/OX**: ① "가용성 침해 = DDoS, 랜섬웨어(암호화로 못 쓰게 함)" ② "부인방지는 공개키 '서명'으로, 기밀성은 공개키 '암호화'로" ③ "해시는 무결성 검증, 암호화는 기밀성" — 해시는 복호화 불가(일방향).

**(2) 제로트러스트(Zero Trust)** 
- NIST SP 800-207 「Zero Trust Architecture」 발행 2020년 8월; 핵심은 "암묵적 신뢰를 없애고, 네트워크 위치(내부/외부)와 무관하게 모든 접근 요청을 지속 검증" — [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final) [확인: 발행일 2020.8]
- 국내: 과기정통부·KISA 「제로트러스트 가이드라인 1.0」(2023.7 공개) — 기업망 핵심요소 6가지 = 식별자·신원 / 기기·엔드포인트 / 네트워크 / 시스템 / 애플리케이션·워크로드 / 데이터 — [바이라인네트워크 2023.7](https://byline.network/2023/07/0707_005) [확인]; 가이드라인 2.0은 2024.12 공개(확인 필요)
- 금융권: 금융보안원 「금융분야 제로트러스트 보안 안내서」 발간 **2026.4.9 보도** — 망분리 규제 완화 흐름 속 금융회사가 제로트러스트를 쉽게 구축·운영하도록 지원 목적 — [바이라인네트워크 2026.4.9](https://byline.network/tag/zta/) [확인]. (주의: 2024~2025년 "금융권 제로트러스트 가이드라인"이라는 별도 문서는 이번 세션에서 확인 못 함 → 시험에선 "금융보안원 안내서, 2026.4"로 기억)
- 망분리 완화 연계: 2026.4.20 내부망 SaaS 허용(전자금융감독규정 시행세칙), 2026.5.24 보안목적 AI 활용 시 망분리 한시 완화(1차 10곳 이내·1년), 2026.7.15 망분리 전면 해제 추진 + 디지털금융안전법 제정 방향; 2026.10 해킹 사태로 2차 테스트 선정(10/7 예정) 연기 — 내부 노트 05 §[D] 인용 [쿠키뉴스 1/19](https://www.kukinews.com/article/view/kuk202601190057), [머니투데이 5/24](https://www.mt.co.kr/finance/2026/05/24/2026052401530379068), [디지털데일리 7/15](https://www.ddaily.co.kr/page/view/2026071517443276094), [스마트투데이](https://www.smarttoday.co.kr/ko-kr/articles/112323)
- **함정/OX**: ① "제로트러스트는 VPN으로 내부망에 들어오면 신뢰한다" → X(경계 기반 모델의 설명) ② "NIST SP 800-207은 2020년" ③ "망분리 완화 ↔ 제로트러스트 강화는 상충이 아니라 보완(경계 보안 → 식별·검증 보안)"

**(3) 인증 3요소·MFA·OTP·FIDO·생체** [교과서]
| 구분 | 요소 | 예 |
|---|---|---|
| 지식 기반 Something you know | 비밀번호, PIN, 보안질문 | 로그인 암호 |
| 소유 기반 Something you have | OTP 토큰, 보안카드, 스마트폰, 공동인증서(파일/USB) | 하드웨어 OTP |
| 속성(존재) 기반 Something you are | 지문·얼굴·홍채·정맥 | FIDO 생체인증 |
- MFA(다중요소인증) = 서로 다른 '종류'의 요소 2개 이상; 2FA는 그중 2개. 비밀번호+보안질문은 둘 다 지식 기반이라 MFA가 아님 — [NIST SP 800-63B](https://pages.nist.gov/800-63-3/sp800-63b.html) (본 세션 미열람)
- OTP: 일회용 비밀번호. 하드웨어 OTP(별도 기기), 모바일 OTP(앱), 카드형 OTP(카드 모양 기기). 전자금융 보안등급: 보안카드 < 모바일OTP·카드형 < 하드웨어 OTP 순으로 이체한도가 커지는 구조이나 **금융회사별 매체등급·한도는 각사 약관 기준(확인 필요)**
- FIDO: 공개키 기반 비밀번호 없는 인증. FIDO2 = WebAuthn(W3C 표준 API) + CTAP(인증장치 통신). 패스키(Passkey) = FIDO 자격증명을 기기 간 동기화해 쓰는 형태. 생체정보는 단말 밖으로 나가지 않고 서버엔 공개키만 저장 — [FIDO Alliance](https://fidoalliance.org/fido2/) (본 세션 미열람)
- 생체인증 지표: FAR(타인수락률, 오인식·보안 척도) vs FRR(본인거부률, 편의 척도) — 둘은 트레이드오프, 교차점 EER(동일오류율)
- **함정/OX**: ① "OTP는 소유 기반" ② "FIDO 서버에 지문 이미지가 저장된다" → X ③ "FAR 낮을수록 보안 강함, FRR 낮을수록 편의 높음"

**(4) 전자서명·인증서 비교** 
| 구분 | 공동인증서(구 공인인증서) | 금융인증서 | 민간인증서 |
|---|---|---|---|
| 발급 | 공인인증기관 6곳(금융결제원·코스콤 등) | 금융결제원 | 네이버·카카오·토스·PASS(통신3사)·삼성패스 등 |
| 저장 | PC·USB·스마트폰 파일 | 금융결제원 **클라우드** 보관 | 각 앱 내 |
| 유효기간 | 1년 | 3년 | 사업자별(통상 2~3년) |
| 근거 | 전자서명법(2020.12.10 시행 개정으로 '공인' 독점 폐지, 명칭 '공동') | 전자서명인증사업자 평가·인정 | 전자서명인증사업자 평가·인정 |
- 전자서명법 개정: 2020.5.20 국회 통과, 2020.12.10 시행 → 공인인증서 제도 폐지·모든 전자서명에 동등 효력, '공인'→'공동'인증서로 명칭 변경 — [법제처 전자서명법](https://www.law.go.kr/법령/전자서명법) (본 세션 미열람, 날짜는 통설·확인 권장)
- PKI: 공개키 기반구조. CA(인증기관)가 인증서 발급·폐기, RA(등록기관)가 신원확인, CRL/OCSP로 폐기 확인. 전자서명 = 개인키로 서명, 공개키로 검증.
- **함정/OX**: ① "2020.12 이후 공동인증서는 폐지됐다" → X(독점만 폐지, 여전히 사용) ② "금융인증서는 금융결제원 클라우드에 저장, 유효기간 3년" ③ "전자서명은 공개키로 서명한다" → X(개인키로 서명)

**(5) 암호화 기초** [교과서]
| 구분 | 대칭키 | 비대칭키(공개키) | 해시 |
|---|---|---|---|
| 키 | 암·복호화 같은 키 | 공개키/개인키 쌍 | 키 없음(일방향) |
| 속도 | 빠름 | 느림 | 매우 빠름 |
| 용도 | 대량 데이터 암호화 | 키 교환·전자서명 | 무결성·비밀번호 저장 |
| 알고리즘 | AES(미 NIST 표준, 128/192/256), **SEED(국산, 1999 KISA)**, **ARIA(국산, 국가표준 2004)**, LEA(경량), 3DES | RSA(소인수분해), ECC(타원곡선, 짧은 키), DH(키교환) | SHA-256(SHA-2 계열), SHA-3, **LSH(국산)**; MD5·SHA-1은 취약 |
- 하이브리드 암호: 공개키로 세션키(대칭키)를 교환하고 실제 데이터는 대칭키로 암호화 → SSL/TLS의 원리.
- 블록암호 운영모드: ECB(블록 독립, 패턴 노출 → 비권장), CBC(이전 암호문과 XOR, IV 필요), CTR(카운터, 병렬화 가능), GCM(인증 암호화, TLS 1.3 기본) — [NIST SP 800-38A](https://csrc.nist.gov/pubs/sp/800/38/a/final) (본 세션 미열람)
- SSL/TLS·HTTPS: HTTP + TLS. TLS 1.3(RFC 8446, 2018) 현행 최신; SSL 3.0·TLS 1.0/1.1은 폐기. HTTPS 기본 포트 443(HTTP 80) — [RFC 8446](https://www.rfc-editor.org/rfc/rfc8446) (본 세션 미열람)
- **함정/OX**: ① "SEED·ARIA는 국산 대칭키" ② "RSA는 소인수분해의 어려움, ECC는 이산대수(타원곡선)" ③ "SHA-256은 암호화 알고리즘이다" → X(해시) ④ "ECB 모드가 가장 안전" → X

**(6) 양자내성암호(PQC)·QKD** 
- NIST PQC 최초 표준 3종 발표 **2024.8.13**: FIPS 203 ML-KEM(구 CRYSTALS-Kyber, 키 캡슐화), FIPS 204 ML-DSA(구 CRYSTALS-Dilithium, 서명), FIPS 205 SLH-DSA(구 SPHINCS+, 해시 기반 서명); 4번째 FN-DSA(Falcon, FIPS 206)는 초안 단계 — [NIST FIPS 203](https://csrc.nist.gov/pubs/fips/203/final) (본 세션 미열람, 날짜는 NIST 발표 기준)
- 위협 논리: "선수집 후 해독(Harvest Now, Decrypt Later, HNDL)" — 지금 암호문을 모아 두었다가 양자컴퓨터 상용화 후 해독 — [보안뉴스 2025.7](https://m.boannews.com/html/detail.html?idx=138486) [확인]
- 금융보안원: 2025.7 「양자컴퓨팅 활용 동향」·「PQC 전환 동향」 연구보고서 2종 배포, "국내 금융사가 PQC 전환 준비를 시작할 시점" — [보안뉴스](https://m.boannews.com/html/detail.html?idx=138486) [확인]
- 해외 일정 참고: 미국 NSA(CNSA 2.0) — 2027년부터 신규 도입 국가안보시스템에 양자내성 알고리즘 요구, 비호환 시스템 2030년부터 단계 퇴출 — [보안뉴스](https://m.boannews.com/html/detail.html?idx=138486) [확인]
- 국내 금융권 도입: 라온시큐어가 KDB생명(금융권 첫 PQC 공급, 2026.6)·NH농협손보(2026.7.20 보도)와 계약 — [아시아경제 2026.7.20](https://view.asiae.co.kr/article/2026072008503508676) [확인, 기업 발표]
- 정책: 「양자과학기술 및 양자산업 육성에 관한 법률」 개정법(2026년 11월 시행 예정)에 양자보안체계 구축 근거; KCMVP(국내 암호모듈검증제도) 내 PQC 도입 검증기술 개발 — [아시아경제 2026.7.20](https://view.asiae.co.kr/article/2026072008503508676) [확인]
- 국내 KpqC 공모전: 2022~2024 진행, 2025.1 최종 선정 알고리즘 4종(HAETAE·AIMer 서명, SMAUG-T·NTRU+ KEM) (확인 필요 — 본 세션 미열람)
- 금융권 PQC 전환 로드맵(2025~): 금융위·금융보안원의 공식 단계별 로드맵 문서는 **이번 세션에서 확인 못 함**(확인 필요). 정부 「범국가 PQC 전환 마스터플랜」(2025.1, 2035년까지 전환 목표) — 확인 필요
- QKD(양자키분배): 양자역학(광자 상태)으로 키를 분배해 도청 시 상태가 변해 탐지. PQC(수학적 난제 기반 소프트웨어)와 구분. **함정**: "PQC는 양자컴퓨터로 돌리는 암호" → X(기존 컴퓨터에서 동작, 양자공격에 '내성')

## 핵심 질문 5. IT 기초(네트워크·DB·OS·프로그래밍·자료구조·SW공학·웹·수 체계·컴퓨터 구조) [교과서 — 표준 참조 URL 제시, 본 세션 미열람]

### Takeaway
부산은행 복기 키워드(클라우드 XaaS·하둡·맵리듀스·데이터마이닝·블록체인 퍼블릭/프라이빗·딥러닝)는 '개념 정의형'이며, 2024 D-IT 코딩테스트(SQL WHERE 기초·map·정렬) 폐지로 2026 통합직군은 SQL·자료구조도 객관식 정의형으로 나올 가능성이 높다. 아래는 혼동 비교표 중심.

### Cited Findings
**(1) OSI 7계층 vs TCP/IP 4계층**
| OSI | 기능 | 프로토콜/단위 | 장비 | TCP/IP |
|---|---|---|---|---|
| 7 응용 | 사용자 서비스 | HTTP·HTTPS·FTP·SMTP·DNS·DHCP / 데이터 | 게이트웨이, L7 스위치·WAF | 응용 |
| 6 표현 | 인코딩·암호화·압축 | SSL/TLS(관점에 따라 5~6), JPEG | | 응용 |
| 5 세션 | 연결 설정·유지 | NetBIOS, RPC | | 응용 |
| 4 전송 | 종단 간 신뢰·흐름제어 | **TCP·UDP** / 세그먼트 | L4 스위치 | 전송 |
| 3 네트워크 | 라우팅·논리주소(IP) | **IP·ICMP·ARP(2.5)** / 패킷 | **라우터**, L3 스위치 | 인터넷 |
| 2 데이터링크 | MAC 주소·오류검출 | Ethernet, PPP / 프레임 | **스위치·브리지** | 네트워크 접근 |
| 1 물리 | 비트 전송 | 케이블, 신호 / 비트 | **허브·리피터** | 네트워크 접근 |
- 참조: [ISO/IEC 7498-1](https://www.iso.org/standard/20269.html), [RFC 1122](https://www.rfc-editor.org/rfc/rfc1122)
- **함정**: 허브(1계층, 모든 포트로 브로드캐스트·충돌) vs 스위치(2계층, MAC 테이블로 목적지 포트만) vs 라우터(3계층, 서로 다른 네트워크 연결·IP 라우팅).

**(2) TCP vs UDP / IP·DNS·DHCP·NAT / HTTP**
| | TCP | UDP |
|---|---|---|
| 연결 | 연결지향(3-way handshake: SYN→SYN+ACK→ACK) | 비연결 |
| 신뢰성 | 순서·재전송 보장 | 보장 없음 |
| 속도 | 느림 | 빠름 |
| 용도 | HTTP·메일·파일 | DNS·스트리밍·VoIP·게임 |
- IPv4(32비트, 약 43억 개, 점 10진 4옥텟) vs IPv6(128비트, 16진 8그룹, 사실상 무한, 헤더 단순화·IPsec 기본 지원). 서브넷 마스크로 네트워크/호스트 분리(예 /24 = 254개 호스트). 사설 IP(10/8, 172.16/12, 192.168/16)는 NAT로 공인 IP 변환 — [RFC 1918](https://www.rfc-editor.org/rfc/rfc1918)
- DNS: 도메인→IP 변환(53번, 주로 UDP). DHCP: IP 자동 할당(67/68). ARP: IP→MAC.
- HTTP(80, 평문) vs HTTPS(443, TLS 암호화). HTTP 메서드: GET(조회·멱등), POST(생성), PUT(전체 수정), PATCH(부분 수정), DELETE. 상태코드: 1xx 정보, **200 OK, 201 Created, 301 영구이동, 302 임시이동, 400 잘못된 요청, 401 인증 필요, 403 금지(권한), 404 없음, 500 서버오류, 503 서비스 불가** — [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110)
- **함정**: 401(Unauthorized)은 '인증' 실패, 403(Forbidden)은 '인가' 실패.
- 클라이언트-서버(중앙 서버가 서비스 제공) vs P2P(동등 노드 간 직접, 블록체인·토렌트).

**(3) 데이터베이스**
| 구분 | RDBMS | NoSQL |
|---|---|---|
| 모델 | 표(행·열), 스키마 고정 | 키-값·문서·컬럼·그래프, 스키마 유연 |
| 언어 | SQL | 제품별 API |
| 확장 | 수직(Scale-up) 중심 | 수평(Scale-out) 용이 |
| 일관성 | ACID 강함 | BASE·결과적 일관성 |
| 예 | Oracle, MySQL, PostgreSQL | MongoDB, Redis, Cassandra, Neo4j |
- SQL 분류: **DDL**(CREATE·ALTER·DROP·TRUNCATE) / **DML**(SELECT·INSERT·UPDATE·DELETE) / **DCL**(GRANT·REVOKE) / TCL(COMMIT·ROLLBACK). **함정**: "DELETE는 DDL" → X(DML), TRUNCATE는 DDL; "SELECT는 DQL로 따로 분류하기도".
- 키: 기본키(유일+NOT NULL, 테이블당 1개), 후보키, 대체키, 외래키(다른 테이블 기본키 참조 → 참조 무결성), 슈퍼키. 
- 정규화: 중복 제거·이상(삽입·갱신·삭제 anomaly) 방지. 1NF 원자값 → 2NF 부분함수종속 제거 → 3NF 이행함수종속 제거 → BCNF 결정자가 후보키. 반정규화 = 성능 위해 의도적 중복.
- 트랜잭션 ACID: 원자성(전부/전무), 일관성, 격리성, 지속성. 인덱스: 검색 속도↑, 삽입·갱신 비용↑, B-tree 구조.
- 하둡(HDFS+MapReduce, 분산 저장·처리), 맵리듀스(Map 분할처리 → Reduce 집계), 데이터마이닝(대량 데이터에서 패턴 발견: 분류·군집·연관규칙), 데이터 웨어하우스 vs 데이터 레이크(정형·가공 vs 원본 그대로) — 복기 빈출(내부 노트 08).

**(4) 운영체제**
- 프로세스(실행 중 프로그램, 독립 메모리) vs 스레드(프로세스 내 실행 단위, 메모리 공유 → 문맥교환 비용 작음). 가상메모리(디스크를 메모리처럼, 페이징·스와핑). 데드락 4조건: 상호배제·점유대기·비선점·순환대기(하나만 깨면 예방). 스케줄링: FCFS·SJF·라운드로빈(시분할)·우선순위. **함정**: "스레드는 서로 메모리를 공유하지 않는다" → X.

**(5) 프로그래밍·개발 방법론**
| 비교 | A | B |
|---|---|---|
| 컴파일러 vs 인터프리터 | 전체 번역 후 실행(C·Java(바이트코드)), 빠름 | 한 줄씩 해석·실행(Python·JS), 유연 |

| 오픈소스 라이선스 | **GPL**(카피레프트, 2차 저작물도 공개) | **MIT·Apache·BSD**(허용적, 고지만) |
- SDLC: 요구분석→설계→구현→테스트→유지보수. 테스트 단계(V모델): **단위→통합→시스템→인수(알파·베타)**. 블랙박스(기능) vs 화이트박스(내부 구조).
- 자료구조: 스택(LIFO, 재귀·undo), 큐(FIFO, 프린터·BFS), 연결리스트(삽입삭제 O(1), 탐색 O(n)), 트리(계층, 이진탐색트리 O(log n)), 해시(키→인덱스, 평균 O(1), 충돌), 그래프(정점·간선, BFS/DFS).
- 정렬: 버블·선택·삽입 O(n²), 퀵(평균 n log n, 최악 n²)·병합(n log n, 안정)·힙. 탐색: 선형 O(n), 이진 O(log n, 정렬 필요). 빅오: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ).

**(6) 웹·인증 토큰**

**(7) 수 체계·문자 코드·컴퓨터 구조**
- 비트(0/1)·바이트(8비트, 0~255). 2진수 1010 = 10, 16진수 FF = 255 = 2진 11111111; 16진 한 자리 = 4비트. 1KB=1,024B(KiB) vs 1,000B(SI) 혼용. ASCII 7비트 128자(영문) → 유니코드(전 세계 문자 코드 포인트) → UTF-8(가변 1~4바이트, ASCII 호환, 한글 3바이트), UTF-16(2·4바이트), EUC-KR(완성형 한글 2바이트).
- CPU(범용 순차·분기, 코어 소수) vs GPU(병렬 연산, AI 학습) vs NPU(신경망 전용 저전력 추론, 온디바이스 AI). 메모리 계층: 레지스터 > 캐시(L1·L2·L3, SRAM) > 주기억장치 RAM(휘발, DRAM) > SSD/HDD(비휘발). ROM(읽기 전용, 펌웨어·BIOS). SSD(플래시, 무소음·고속) vs HDD(자기 디스크). 무어의 법칙(18~24개월 트랜지스터 2배).
